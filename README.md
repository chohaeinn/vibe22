# 🎪 INCLUSE · AI Festival Designer

행사장 정보를 입력하고 3D 배치도를 만들며 시설을 직접 수정하는 **Streamlit 교육용 시제품**이다. 첨부 개발 계획서의 핵심 기능과 참고 이미지의 밝은 대시보드·입체 행사장 구성을 반영했다.

> 참고 이미지와 똑같은 일러스트를 띄우는 사이트가 아니다. 회전·확대 가능한 실제 좌표 기반 3D 도형을 그린다. 사진 수준의 모델, 드래그 편집, 실제 지형 복제는 포함하지 않는다.

## 1. 가장 빠른 배포 방법

1. ZIP을 풀고 GitHub에서 새 저장소를 만든다.
2. 압축 안의 **파일과 폴더를 그대로** 저장소에 업로드한다. ZIP 파일만 올리지 않는다.
3. 저장소 최상단에 `app.py`, `engine.py`, `views.py`, `requirements.txt`가 있도록 한다.
4. Streamlit Community Cloud에 GitHub 계정으로 로그인한다.
5. 새 앱 배포 화면에서 해당 저장소·브랜치를 선택한다.
6. 실행 파일 경로를 `app.py`로 지정하고 배포한다. Python 3.11 또는 3.12를 권장한다.
7. 배포 완료 후 생성된 앱 주소에 접속한다.

메뉴 이름은 서비스 업데이트에 따라 달라질 수 있다. GitHub Pages는 Python 서버를 실행하지 않으므로 이 앱의 배포 방식으로 사용하지 않는다.

## 2. 내 컴퓨터에서 실행

Python 3.11 또는 3.12 환경의 프로젝트 폴더에서 실행한다.

```bash
python -m venv .venv
```

Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```

macOS/Linux:
```bash
source .venv/bin/activate
```

이후 공통:
```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

## 3. 사용 순서

1. 왼쪽에서 행사명, 부지 크기, 하루 방문객, 동시 체류 비율, 예산을 입력한다.
2. `시설 종류·수량`을 펼쳐 원하는 수량을 정한다.
3. **입력 적용 · 새 배치 생성**을 누른다. 현재 배치는 대체된다.
4. 3D 설계도에서 회전·확대하고 시설 종류별 표시를 바꾼다.
5. **자동 배치 최적화**를 누르면 30개 후보를 비교한다. 같은 수량의 기존 배치가 더 좋으면 기존 배치를 유지할 수 있다.
6. `시설 편집`에서 위치·크기·높이·가상 비용을 수정하거나 시설을 추가·삭제한다.
7. `상황 분석`에서 상황별 정적 밀도 분포와 개선 조언을 확인한다.
8. `전후 비교`에서 최적화 직전과 현재를 비교한다.
9. `저장·불러오기`에서 JSON, CSV, HTML 보고서를 내려받는다.

**반드시 JSON을 내려받아 보관한다.** 저장 버튼은 다운로드를 뜻한다. GitHub 저장소나 서버 DB에 자동 저장하지 않는다. 새 세션·재배포·서버 재시작 시 메모리 상태가 사라질 수 있다.

### 포함된 시설
무대, 관람석, 판매 부스, 체험 부스, 푸드트럭, 휴식 공간, 화장실, 안내소, 응급의료소, 출입구, 주차장, 분리수거장, 음수대.

기본값은 160×120m, 하루 방문객 3,000명, 동시 체류 30%, 예산 2,000만원, 총 33개 시설이다. 모두 데모 입력값이며 실제 행사 데이터가 아니다.

### 시설 편집 방식
시설을 선택하고 X/Y·가로/세로·높이를 숫자로 수정한 뒤 저장한다. 3D 모델을 마우스로 끌어서 이동시키는 기능은 없다. 중앙 십자 통로를 가로지르거나 시설 간 간격이 부족한 수정은 거부한다. 좌표 단위는 m이다.

## 4. 선택 기능: 외부 자연어 AI 연결

키가 없어도 배치·편집·비교·파일 저장 기능이 작동한다. 연결하지 않으면 상담 버튼은 **규칙 기반 안내만** 보여 주고, 사용자의 자유로운 문장은 해석하지 않는다.

외부 AI를 쓰려면 운영 중인 서비스에서 **chat-completions 호환 HTTPS API**와 모델명을 준비하고 앱의 Secrets에 아래 값을 추가한다. URL은 완전한 요청 경로까지 입력한다.

```toml
AI_API_URL = "https://YOUR_SERVICE_HOST/YOUR_CHAT_COMPLETIONS_PATH"
AI_API_KEY = "YOUR_PRIVATE_KEY"
AI_MODEL = "YOUR_MODEL_NAME"
```

위 값은 예시 자리표시자이며 실제 서비스 주소가 아니다. 사용 중인 API 서비스의 실제 값으로 바꿔야 한다. 다른 요청/응답 형식의 API는 `app.py`의 상담 요청 부분을 수정해야 한다.

- 로컬: `.streamlit/secrets.toml` 생성.
- 배포: 배포 서비스의 앱 설정에서 Secrets 입력.
- `secrets.example.toml`은 참고용이다. 실제 키는 **절대 GitHub에 업로드하지 않는다.**
- 버튼을 누를 때 요구사항, 행사 설정, 비교 지표, 시설명·종류·좌표·크기가 외부 API로 전송된다. 개인정보나 민감한 행사 정보는 입력하지 않는다.
- 자연어 AI는 설명만 제공한다. 시설 좌표를 자동 변경하지 않는다.
- 외부 API 사용료·약관은 해당 서비스에 따른다.

## 6. 수식과 가정

- 가상 설치비: `engine.py`의 `KINDS`에 정의한 임의 단가 합계. 견적이나 실제 시장가격이 아니다.
- 여유면적: 부지 면적에서 배치 시설 바닥 면적을 뺀 값.
- 평균 밀도: 하루 방문객 × 가정 동시 체류 비율 ÷ 여유면적.
- 배치 여유: `100 - 오류 수×12 - 누락 필수시설 종류×10 - max(0,밀도-0.3)×45`.
- 휴식 접근 비율: 중심 기준 30m 안에 휴식 공간이 있는 시설 비율.
- 입구 거리: 시설 중심에서 가장 가까운 출입구 중심까지 직선거리 평균.
- 근접성: `휴식 접근 비율×0.6 + max(0,100-입구 거리×0.7)×0.4`.
- 이동 편의: `100-입구 거리×0.65-max(0,밀도-0.3)×30`.
- 예산 적합: `min(100,입력 예산/가상 설치비×100)`.
- 점수는 0~100으로 제한한다. 안전 중심·접근성 중심·운영 효율 중심은 선택 항목 0.5, 다른 두 항목 각 0.2, 예산 0.1이다. 예산 중심은 배치 여유 0.2·근접성 0.2·이동 편의 0.1·예산 0.5이다.
- 미배치 시설 하나마다 후보 선택값에서 100을 감점한다. 배치하지 못한 수량은 화면에 표시한다.
- 밀도 지도는 무대·관람석·푸드트럭·출입구에 더 큰 집중 가중치를 가정하고 전체 체류 인원에 맞춰 정규화한다. 장애물·실제 보행 가능 영역을 반영하지 않는다.
- 급증 시 지도 밀도 1.5배, 우천 시 1.2배. 공연 지연 시 무대·관람석의 상대 가중치 1.6배. 응급상황은 밀도를 바꾸지 않고 운영상 검토 항목을 안내한다.

계획서의 장기 목표를 모두 완성한 제품이 아니라, 위 가정을 확인하며 확장할 수 있는 실행 가능한 초기 코드다.

## 8. 테스트

```bash
python -m unittest discover -s tests -v
```

코드 제작 시 배치 엔진 단위 테스트 8개, Python 문법 검사, Plotly 3D/2D 직렬화 검사를 통과했다. 제작 환경에는 Streamlit이 없어 실제 화면 구동 검사는 실행하지 못했다. 포함된 GitHub Actions는 의존성을 설치한 뒤 Streamlit 초기 구동과 기본 상호작용까지 검사한다. GitHub의 Actions 탭에서 결과를 확인한다. 자동 검사 통과도 시각적 완성도나 실제 안전성을 보장하지 않는다.

## 9. 흔한 문제

- **No module named ...**: `python -m pip install -r requirements.txt` 실행.
- **배포 후 파일을 찾을 수 없음**: 실행 경로와 세 Python 파일이 같은 폴더인지 확인.
- **시설이 일부 빠짐**: 경계·중앙 통로·시설 간 여유를 만족할 공간이 부족한 것이다. 수량을 줄이거나 부지를 넓힌다.
- **새로고침 뒤 설계가 사라짐**: JSON 파일을 불러온다. 서버 영구저장이 아니다.
- **AI 연결 실패**: Secrets의 완전한 API 경로·모델·키·요청 호환 여부 확인.
- **그림이 참고 이미지와 다름**: 경량 도형 기반 구현이다. 고급 3D 에셋과 직접 드래그 편집은 별도 프론트엔드 개발이 필요하다.
